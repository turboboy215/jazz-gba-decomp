# Jazz Jackrabbit (GBA) decompilation

A work-in-progress **matching decompilation** of *Jazz Jackrabbit* for the Game Boy Advance
(USA, `AJJE`, Game Titan / Jaleco 2002, GAX audio by Shin'en), with labels and documentation
and a planned native PC port.

The build is **byte-identical** to the original ROM:

```
$ make compare
jazz.gba: OK
```

| | |
|---|---|
| Target ROM | `Jazz Jackrabbit (U).gba`, SHA1 `9fb012b46350615cfa4dd0fc7d11fc21903d39e0` |
| Compiler | pret `old_agbcc` `-O2 -mthumb-interwork -fno-merge-blocks -fdelete-dead-after-reload -fgcse-no-const -fno-strict-aliasing -fcombine-givs-fix -fgcse-insert-before-copy -fgiv-keep-after-exit -fgcse-const-in-loops -fold-base-reg-class -fcprop-const-fix -fcprop-single-set` (identified by matching; see `docs/STRATEGY.md`) |
| Progress | `make progress` (C bytes / live code bytes; the multiboot client image is excluded) |

This repository contains **no ROM data**. Bring your own copy.

## Building

Requirements: a Unix-like shell (Linux, macOS, or WSL on Windows), Python 3, `arm-none-eabi` binutils
and `arm-none-eabi-cpp` (Debian/Ubuntu: `gcc-arm-none-eabi binutils-arm-none-eabi`), and pret's agbcc
with a small patch that adds `-fno-merge-blocks` and `-fdelete-dead-after-reload` (`tools/agbcc-jazz.patch`;
the ROM's compiler predates two Cygnus changes in pret's tree). `tools/build_agbcc.sh` clones, patches, builds and installs it.

```sh
sh tools/build_agbcc.sh            # pret/agbcc + tools/agbcc-jazz.patch -> tools/agbcc
cp "Jazz Jackrabbit (U).gba" baserom.gba
make -j$(nproc) compare
```

## Layout

| Path | |
|---|---|
| `asm/` | disassembly generated by `tools/split.py` from `decomp/functions.csv` + `splits.txt` + `names.txt` (labelled) |
| `src/` | matched C: region A by subsystem (`sprite.c`, `oam_1.c`, ...; `tools/subsystems.py`), GAX in `src/gax/` by original module (`gax`, `sync`, `output`, `tracker`; `docs/gax.md`), region B per run (`code_<addr>.c`) |
| `include/` | headers (`global.h`, `gax.h` public GAX API, `gax_internal.h` GAX internals, `main.h` region B) |
| `data/` | `.incbin` of the graphics/level data between the code regions |
| `names.txt` | function names and comments → alias labels in the asm |
| `splits.txt` | C/asm ranges and link order |
| `docs/HANDOFF.md` | **start here** in a new session: setup, verified facts, next tasks |
| `docs/boot_sequence.md` | power-on to main menu as seen on screen, mapped to the functions |
| `docs/songs.md` | songs, internal vs actual names, level table with level names |
| `docs/rom_map.md` | memory map, sections, crt0, interrupts, veneers, libraries, **the multiboot client image** |
| `docs/gax.md` | the GAX 3.01 sound engine: both copies, function map, how the game uses it |
| `docs/strings.tsv` | all ASCII text (dialogue, menus, credits) |
| `docs/STRATEGY.md` | project log: compiler evidence, tool changes, work order |
| `docs/PC_PORT.md` | native port plan (PC first, then PlayStation) |
| `docs/reference/` | the generic `gba-matching-decomp` playbook (strategy log + agbcc matching tips) |

## Workflow (per function)

```sh
flock .decomp.lock python3 tools/claim.py              # next function: ADDR END SIZE
# write C in a scratch file (start from decomp/drafts/ADDR.c if you ran the Ghidra pass)
python3 tools/check_func.py scratch.c ADDR             # MATCH / side-by-side diff
sh tools/integrate_one.sh ADDR scratch.c Name          # add to src/, make compare, commit
```

Ghidra (11.x, headless) produces `decomp/functions.csv` and the C drafts; see the commands in
`docs/reference/STRATEGY.md` and `tools/scripts/`.
